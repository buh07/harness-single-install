# Harness outcome workflow — v3

**Outer conversation is outside the workflow.** It submits the entire original
request unchanged and relays the truthful final result. It does not plan, inspect
product code, manage lanes/events, check, integrate, route repairs, watch, or shut
down. The separate genuine native execution/integration coordinator is the sole
prepared logical ROOT from intake—not a renamed outer conversation or planner.

Newest marked native prompt registers unchanged request/gateway before tools;
this is nonmanager provenance, not a sticky mode or actionable queue. Selection
loads instructions, not a provider launcher or proof of compliance.
Read [native intake/startup](../../docs/WORKFLOW.md#native-intake-and-startup) for
actual session creation, preparation, submission, acceptance and failure paths.
No supported authorized separate native session means BLOCKED; never fabricate
identities, substitute collaboration subagents for native lanes, or make outer do
the selected task. Noncoding selected requests also go to coordinator; it fulfills
them and closes its runtime without inventing a coding contract/lanes. The
planning/coding/audit stages below apply to coding tasks.

## Coordinator: commission planning, not a precomputed answer

1. Accept the exact immutable raw request through the native intake API in the
   designated real coordinator conversation. Preserve original text/constraints,
   authorization and role preferences. Own the native lifecycle from acceptance.
2. Commission a **separate native planner** with one bounded goal: produce the
   complete original-outcome ledger, useful coding cards and whole-result criteria.
   Give it the whole request and relevant context. Each coding card has **one
   concrete task and one concrete checkable outcome**, scope/exclusions,
   dependencies/interfaces, deliverables and real checks. Planner is not manager;
   coordinator alone watches, handles events, settles and retires its lane.
3. Commission a **fresh independent native split reviewer**, read-only-product,
   with the original request, entire proposed ledger, **all** cards, relevant
   context/interfaces and authorized role preferences, including planner. Review
   useful semantic independence, coverage, DAG/shared ownership, one goal per card,
   granularity versus coordination cost and global criteria—not maximum count.
   One small coding lane is valid. Read [planning review](references/planning-review.md).
4. Return justified planning findings to the separate planner for revision or a
   specific reasoned rejection. The coordinator owns communications/lifecycle,
   not decomposition disguised as routing. Material plan changes need review of
   the exact final plan. Freeze the original-task-preserving plan only with actual
   separate planner and reviewer provenance; see [records](references/contract.md).
   Review advice is not a PASS/veto gate. Missing required evidence means honest
   incompleteness, never fabricated approval or indefinite OPEN.

## Coordinator: code, integrate, check

Launch distinct native coding lanes with complete bounded cards and explicit
operator-authorized provider/model/options. Keep one writer per shared path and
sequence dependencies. Use native `watch --until-actionable`, normal RESULT/events,
acknowledgement, completion review and retirement—no relay or transcript watcher.

Read **every** frozen original outcome/card/global criterion. Own a separate
candidate branch/worktree, check and integrate contributions, then check **all
original outcomes and global criteria together**, including interactions and
preserved behavior. Worker-local PASS and Git commits are not task completion or
push/promotion permission.

## Coordinator ↔ fresh independent whole-result auditor

Give a fresh independent read-only-product native auditor the entire original
request/constraints, frozen ledger, **all** cards, relevant context/interfaces,
exact integrated revision, actual checks and known limitations. It independently
checks every original outcome and whether the unified result fulfills the whole
request. Discover its normal native RESULT through native watch.

Judge findings with evidence and reasoned dispositions. **Make justified repairs
yourself**, never through outer, planner or original coders. Any material change
invalidates the prior audit: commit the new exact revision, rerun **all** original
outcome/global checks and commission a **fresh independent native auditor**.
Repeat within authorized resources until the entire unified target works, or
report BLOCKED/INCOMPLETE. Never weaken/drop/relabel requirements, reuse stale
approval, claim partial success as completion, or chase a PASS label indefinitely.

Reviews are advisory, never vetoes. Typed records check declared linkage,
identity, coverage and revision consistency, not evidence truth or semantic
completion. Keep actual commands/statuses, failed reports and reasons for rejected
advice. COMPLETE means every original outcome works together and the whole request
is satisfied with current independent evidence—not merely a verdict or CLOSED.

Coordinator owns all cleanup even when incomplete: settle/retire lanes/events,
run native `harness shutdown` and prove CLOSED. A missing review cannot block
shutdown. Report exact revision, checks/coverage, resolutions, native identities,
limitations and lifecycle proof; outer only relays. No wrapper, scheduler,
supervisor, retry controller, AI watcher, automatic provider retries or invented
permissions. Saved v1/v2 records are history, not v3 intake authority.
